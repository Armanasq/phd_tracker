# EvidenceGraph offline observatory

The dashboard is a generated, **offline, private-data** HTML application. It is not a GitHub README script and not a hosted public website.

## Open it

1. Clone the private repository.
2. If a generated `dashboard/index.html` already exists, open it in a browser.
3. Otherwise run the pipeline with the repository's existing data: `python scripts/experience_engine.py`, then open `dashboard/index.html`.

No web server, API keys, CDN, telemetry, external JavaScript, or GitHub Pages deployment is required. The generated file embeds a schema-versioned snapshot of repository data. **Do not publish or share it**: it may contain private application decisions, research activity, and source records.

## Features

- Search university, application name or stable ID.
- Filter by days-to-deadline and recorded proof states.
- Inspect individual application records, provenance URLs, document mentions, next steps and explicit evidence obligations.
- Visual deadline distribution using the observation date, without conflating tasks and final deadlines.
- Counterfactual document scenario controls. These operate exclusively in browser memory and do not mutate the saved state.
- Discovery-provider observability that preserves degraded and disabled collectors.
- Research signals separated from actual funded opportunities.

## Integrity constraints

The view is built from `data/execution_plan.json`, `data/portfolio_frontier.json`, `data/application_assets.json`, `data/discovery_report.json`, `data/latest_run.json`, and `data/research_radar.json`. The main planner and frontier must have the same observation date. Application IDs must be unique, and owner-confirmed states are never inferred from advertisements. Only HTTPS source links are accepted.

The local dashboard shows the *snapshot date*, which is not the current date after the file ages. Re-run generation after repository data changes. Do not interpret document coverage as eligibility or application completion.

## Engineering and design

Generated by `scripts/experience_engine.py` from `dashboard/template.html`. GitHub Actions regenerates and commits `dashboard/index.html`, `data/experience_view.json`, `assets/readme/evidence_pipeline.gif`, and visual assets as part of the existing atomic intelligence pipeline. The README uses the image assets and links to the local usage instructions.

The dashboard intentionally has no persistence, signup, third-party requests or remote state mutation. Real user status changes continue through the repository's existing owner-validated Action Center.

The design combines known techniques (temporal views, proof obligation tracking, counterfactual resource coverage, and failure-aware observability). It does not assert global technical novelty or measured predictive performance.
